# Claude View

![claude demo](../../../../assets/demo-claude.gif)

このリポジトリで Claude Code が何をしているかを、transcript から読み取って
表示するビューです。**作業ディレクトリがこのリポジトリか、その worktree の
配下（サブディレクトリを含む）にあるセッションすべて**を、最後に更新された
順に並べ、作業に追従します。`claude` の起動・`/clear`・`--fork-session` は
新しいセッションになり、`--continue` / `--resume`・コンパクション・
サブエージェントは同じセッションのままです。

セッションを読むには transcript 全体を読む必要があるので、すべての
セッションを読むわけではありません。最後に更新された 3 つは最初から読んで
展開し、それ以外は行を開いたとき（`Enter`）に読みます。一度読んだ
セッションは読んだままで、以後は追従します。

ペインの上の 1 行は、選択がいるセッションの概要です:

```text
Add retry with backoff to the fetcher · opus-5-5 · ● active · ctx ▓▓▓░░░░░ 33% · ~$1.75 · feat/retry-backoff
```

| 項目 | 意味 |
|---|---|
| タイトル | セッションのタイトル（Claude Code が付けたもの、または自分で付けたもの） |
| モデル | 最新の応答のモデル |
| 状態 | [ライブイベント](#ライブイベント)があるとき: `● working`、`● running Bash`、`▲ approve Bash?`（ツール呼び出しが承認待ち）、`○ waiting for input`。無いとき: `● active` — 直近 1 分以内に transcript へ書き込みがあった。`○ quiet 5m00s` — 最後の書き込みからの経過時間。`■ exited` — Claude Code が終了した。transcript だけでは、長いツール実行と入力待ちを区別できません |
| `ctx` | 最新の応答時点のコンテキスト使用量（モデルのウィンドウに対する割合） |
| コスト | Claude Code 自身が書いた合計があればそれ。`~` は価格表からの見積りを含む値。モデルの価格が不明なら `$—` |
| ブランチ | セッションが動いているブランチ |

## ペイン

- **Interactions** — セッションと、その下に各セッションの直近の
  インタラクションを新しい順に並べます。セッションの行は、最後に書き込まれた
  時刻、リポジトリのルート以外で動いていればその場所（サブディレクトリ、
  または別の worktree のディレクトリ名）、タイトル、インタラクションの
  LLM リクエスト数とツール呼び出し数、状態（`active` / `quiet` /
  `exited`）を表示します。読んでいないセッションは `not read` と出ます。
  セッションの行で `Enter` を押すと、そのセッションを読み、読んだあとは
  折りたたみ / 展開します（`Space` はセッション内のどの行からでも同じ
  操作です）。インタラクションは、1 つのプロンプトと、それに答えるために
  行われたすべてです。その行は、開始時刻、何を頼んだか（プロンプトの
  1 行目）、メインスレッドの LLM リクエスト数とツール呼び出し数、所要時間、
  終わり方を表示します: `done`（Claude Code が所要時間を記録した）、
  `running`（終わりがまだ無く、セッションに書き込みが続いている）、
  `no end`（途中で切れた、または終わりまで読めていない）。インタラクションの
  行で `Enter` / `i` を押すとツリーに入ります。`t` で、読んだセッションの
  インタラクションをまとめて新しい順に並べる表示と切り替えます。選択が
  先頭のインタラクションにある間は最新のインタラクションに追従し、動かすと
  その場に留まります。
- **Trace** — 選択中のインタラクションを、起きた順のツリーで表示します。
  LLM リクエストの行は、その応答が何をしたか（`thinking 12.0s → Read, Bash`。
  `claude-text "full"` では応答の 1 行目）と、止まり方（`tool_use`、
  `end_turn`。それ以外は赤）を表示します。その応答が呼んだツールは下に
  ぶら下がります: `✓` / `✗`（結果がまだ無ければ `·`）、ツール名、実行した
  もの、所要時間。サブエージェントは、それを起動した呼び出しの下に入ります
  （`↳ Explore  <タスク>`）。`Space` でその中身を表示 / 隠します。
  `context rebuilt` と `shape changed` は、前のリクエストの続きではない
  リクエスト（コンパクション後など）や、システムプロンプト・ツールが
  変わったリクエストの印です。右側には、インタラクションの長さの時間軸上の
  バーが行ごとに出ます（ペインが狭いときは省略）。
- **Detail** — 選んでいるものの詳細です。セッションの行では、id・動いて
  いる場所・ブランチ・モデル・状態・コンテキスト・コスト。インタラクション
  では、所要時間とその内訳（LLM リクエスト、ツール
  呼び出し、残り）、サブエージェント数、トークン、見積りコスト。フォーカスが
  Trace にあるときはその行: リクエストのモデル・止まり方・トークン・コスト、
  ツール呼び出しのコマンド全体（全行）と、`claude-text "full"` では
  返したもの、サブエージェントのタスク・状態・トークン・コスト。
  `j` / `k` でスクロールします。
- **Files** — 選択中のセッションが読んだ（`R`）・編集した（`E`）・書いた（`W`）
  ファイルを、最後に触った順に並べます。最も強い触り方、触ったツール呼び出し
  の数、経過時間を表示します。パスはリポジトリからの相対です（リポジトリ
  の外は `~/…`）。対象は
  `Read`・`Edit`・`MultiEdit`・`NotebookEdit`・`Write` ツールだけで、
  シェルコマンドが触ったファイルは分かりません。

1 つのセッションが保持するのは、直近 100 件のインタラクション（スレッドごとに
500 スパンまで）と、Files ペインの元になる直近 2000 件のツール呼び出し
です。LLM リクエストの所要時間は近似値です。transcript が記録しているのは
ブロックが書かれた時刻で、API が応答した時刻ではありません。

## どこまでテキストを表示するか

transcript には会話そのものが入っているので、どこまで画面に出すかは設定で
決めます。[`claude-text`](config-reference.md#claude-text) で段階を決めます:

| 段階 | 表示するもの |
|---|---|
| `"summary"`（デフォルト） | セッションのタイトル、各プロンプトの 1 行目、各ツール呼び出しが何を実行したか（ツリーでは 1 行、Detail ではコマンド全体）、ファイルパス、各サブエージェントのタスク |
| `"title"` | セッションのタイトル・ツール名・ファイルパスだけ（画面共有向け） |
| `"full"` | 加えて、各応答の 1 行目と、各ツール呼び出しが返したものの先頭（4000 文字まで、stderr つき）。`o` でその全文を読む |

`"full"` 未満では、応答とツールの出力はビューに読み込まれません。`"full"`
では、ツール呼び出しやリクエストの上で `o` を押すと、全文を transcript から
読み（Claude Code が別ファイルへ退避した出力も含む）、Detail に表示し、
別のものを選ぶと破棄します。もう一度 `o` を押すと先頭だけの表示に
戻ります。ツールの出力は出力されたとおりに表示します。コマンドが秘密情報や
環境変数を書き出していれば、それも画面に出ます。`/` の検索対象は一覧に
表示されているものだけで、Detail ペインは対象外です。

## キーバインド

| キー | 操作 |
|------|------|
| `Tab` / `Shift+Tab` | ペイン切り替え: Interactions → Trace → Detail → Files |
| `j` / `k`、`gg` / `G`、`Ctrl+d` / `Ctrl+u` | 選択移動（Detail ではスクロール） |
| `Enter` / `i`（interactions） | インタラクションではツリーに入る。セッションでは読み込み、折りたたみ / 展開 |
| `Space`（interactions） | セッションを折りたたむ / 開く |
| `t`（interactions） | インタラクションをセッションごと / まとめて表示 |
| `Space`（trace） | サブエージェントの中身を表示 / 隠す |
| `Enter` / `i` / `l`（trace） | 詳細に入る |
| `h` / `Esc`（trace・detail） | 戻る |
| `o`（trace・detail） | 出力 / 応答の全文を読む。もう一度押すと先頭だけに戻る（`claude-text "full"`） |
| `y`（files） | パスをコピー |
| `/` `n` `N` | フォーカス中のペインを検索 |
| `r` | やり直し: セッションを再列挙し、transcript を読み直す |

## ライブイベント

transcript から分かるのは起きたことです。セッションが**いま**何をしているかは、
Claude Code の `iktinos-bridge` mod を入れていると届きます:

```bash
claude plugin install iktinos-bridge --marketplace td72/iktinos
```

Claude ビューを一度開くと、vig は自分用の Unix ソケット
（`~/.local/state/iktinos/sockets/<pid>.sock`。vig の終了時に削除）で
待ち受けます。mod は各イベントをそのディレクトリのソケットすべてに送るので、
vig と単体の `iktinos` ビューアは同じイベントを受け取ります。vig は受け取る
だけです。イベントに載るのは名前・id・数値・ツール呼び出しの 1 行要約で、
プロンプト・応答・出力は載りません。

これにより、セッションが作業中か、ツールを実行中か、承認待ちか、入力待ちか、
実際のウィンドウに対するコンテキスト使用量、レートリミット（Detail の
セッション行）が分かります。ソケットが開いているだけでは mod が送っているか
分からないので、ステータスバーの末尾にソケットが受け取ったものを出します:

| ステータスバー | 意味 |
|---|---|
| `live off` | 待ち受けていない（[`claude-live "off"`](config-reference.md#claude-live)） |
| `live failed` | ソケットを開けなかった |
| `live on, no events yet` | 待ち受けているが何も届いていない: mod が入っていない、無効になっている、またはそれ以降どのセッションも動いていない |
| `live 128 events, last 3s ago` | 受信中。セッションが作業中なのに 1 分間何も届かないと黄色になる |

件数はこのマシンの全セッションの合計です。他のリポジトリのセッションや、
読んでいないセッションのイベントは、数えるだけで使いません。mod が無ければ、
ビューは transcript だけで動きます。

## transcript の場所

Claude Code はセッションごとに 1 つの JSON Lines ファイルを
`~/.claude/projects/`（`$CLAUDE_CONFIG_DIR` があれば
`$CLAUDE_CONFIG_DIR/projects`）に置きます。
[`claude-projects-dir`](config-reference.md#claude-projects-dir) で別の
場所を指定できます。ビューを表示している間、ファイルは 1 秒ごとに
（追記された分だけ）読まれ、ディレクトリは数秒ごとに再列挙されます。
セッションがこのリポジトリのものかどうかは作業ディレクトリで判定します:
リポジトリの配下にあるか、同じ `.git` を共有する worktree の中にあるか
です。
読み取りは [iktinos](https://github.com/td72/iktinos) の `iktinos-core` crate が
行います。

ディレクトリが無い場合や、このリポジトリのセッションがまだ無い場合は、
空のペインの代わりにその旨を表示します。

## 制約

- 読み取り専用です。Claude Code のディレクトリには何も書かず、Claude Code
  には何も送りません。
- 応答とツールの出力を読むのは `claude-text "full"` のときだけです。vig
  自身が環境変数を読むことはありません。ツールが出力したものはそのまま
  表示します。
- `iktinos-bridge` mod が無いとき、状態は transcript が示す範囲です。
  入力待ちかどうか、いま実行中のツール、レートリミットには
  [ライブイベント](#ライブイベント)が必要です。
- このビューのために vig が作るものは自分のソケットファイル 1 つだけです。
  Claude Code のディレクトリの外にあり、終了時に削除します。
- 他のリポジトリのセッションは一覧に出ません。
